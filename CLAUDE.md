# Assetrix — Project Context for Claude

## Что это
Self-hosted PWA для учёта активов (часть экосистемы Mycorium, позже модуль FlowERP). Инструмент IT-техника: быстрый учёт через QR/штрихкод, пакетные операции, неизменяемая история. **Не enterprise-система** — приоритет скорости и простоты.

Метрики: одиночная операция со смартфона — 3–5 с; отклик на скан в пакетном режиме — ≤ 1 с; до 50 000 активов.

Подход: «на коленке», но готово к работе → испытания на реальных задачах → итерации → перенос на Rust + PostgreSQL.

- Лицензионные ключи в P1 не импортируются (D14).

## Ключевые правила (подробности в спеке v2)
- **Event sourcing строго для активов:** события не изменяются и не удаляются (триггеры в БД + 405 в API); исправления — новыми событиями (`CORRECTED`, `UPDATED`); кеш состояния в `assets` пересчитывается командой recalculate.
- **Идентификация:** собственный `asset_code` (кодируется в QR) + таблица внешних идентификаторов со схемами (`invent_num`, `service_tag`, `serial_num`, `license_key`, `vin_code`…). Скан ищет по обоим.
- **Состояние актива:** `physical_condition` + `operational_status` + держатель (сотрудник или отдел) + баланс (отдел) + склад (опционально) + местоположение (дерево). Склад никогда не держатель.
- **Ничего не перемещается неявно:** при выдаче и смене отдела система спрашивает, по умолчанию — без изменений.
- **Склады:** опциональны, многие-ко-многим с отделами, у нового отдела — виртуальный склад по умолчанию. Адресация и условия хранения — pro, не в P1.
- **P1 — один пользователь** (за `basic_auth` в Caddy), но `created_by` и таблица `users` есть с самого начала. Роли — в P2.

## Стек
- **Пилот:** Python 3.12, `uv`, `ruff`, `pytest`; FastAPI + Jinja2 + htmx; SQLite (WAL); миграции на чистом SQL, совместимые с `sqlx migrate`; без ORM.
- **Финал:** Rust (Axum + Askama + htmx, sqlx) + PostgreSQL.
- **Общее:** Caddy (wildcard-сертификат через DNS-01 Porkbun), Docker Compose на Linux.

## UX-правила
- Mobile-first, управление одной рукой, кнопки внизу экрана.
- ≤ 3 клика до любого стандартного действия.
- Звук + вибрация + цвет на каждый скан; крупные touch-элементы, минимум текста.
